# 꿀시간표 백엔드 전체 파이프라인 (v2)

> 파일 형식·자료형·열 이름·함수 이름이 이 문서와 [03_interfaces.md](03_interfaces.md)에서 다르면 03을 따른다.

v2 변경: 수업계획서 PDF 자동 수집 + LLM 구조화 추출(A부 2.5) 추가. 추출 결과 중 숫자·예/아니오 항목은 시간표 제작에 쓰고(B부 3.11), 나머지는 사용자가 시간표를 골랐을 때 과목별 강의 스타일·과제·시험 특징으로 정리해 보여준다(B부 8).

성균관대 전자시간표 공개 데이터로 **A. 과목 데이터를 만들고 → B. 조건에 맞는 시간표를 만들어 고르게 하고 → C. 고른 시간표의 수강신청 전략을 짠다.** 세 단계는 앞 단계의 결과 파일·표를 그대로 받아 쓰는 하나의 흐름이다.

- 팀: 꿀 시간표 (김지후, 이유찬) · 저장소: https://github.com/lynnpield-lang/Timetable-maker
- 원칙
  - 학교 서버에는 학기당 한 번만 접속한다 (A부 build). 앱은 저장된 CSV만 읽는다.
  - 로그인이 필요한 사이트(GLS, 에브리타임)에는 접속하지 않는다. 로그인 화면의 정보(정원·신청 인원)는 사용자가 캡처해서 올린다.
  - 숫자는 모두 코드가 계산하고, LLM은 이미지 읽기와 설명에만 쓴다.

## 한눈에 보는 전체 흐름

```
┌─ A. 데이터 (학기당 1회, 오프라인) ──────────────────────────────────────────┐
│ 학과 코드 → 과목 목록 → 수업계획서 → SSV 파싱 → 정규화·병합 → 검증 → 저장    │
│              └→ 계획서 PDF → 텍스트 → LLM 구조화 추출 → 근거 검증 ┘           │
│                       ⇒ data/courses_<학기>.csv  (시간표 제작용 항목)        │
│                       ⇒ data/profiles_<학기>.jsonl (상세 보기용 항목)        │
└──────────────────────────────────────────────────────────────────────────────┘
          │
┌─ B. 시간표 (앱 실행 중) ─────────────────────────────────────────────────────┐
│ 사용자 정보·과목 선택 → 수강 자격 거르기 → 같은 시간 묶기 → 조합 생성(가지치기) │
│ → 특징 계산 ⇒ 특징표 → 필터 → 우선순위 정렬 → 같은 모양 묶기                  │
│                                              ⇒ 정렬된 시간표 집합 𝒯_f, 목표 T* │
│ 시간표 하나 선택 → 상세 보기 (과목별 강의·과제·시험 특징, 주차별 부담)        │
└──────────────────────────────────────────────────────────────────────────────┘
          │                     ┌─ A'. 캡처 입력 (앱 실행 중) ─────────────┐
          │                     │ 캡처 → LLM 읽기 → 대조 → 사용자 확인       │
          │                     │                    ⇒ competition.csv     │
          │                     └──────────────────────────────────────────┘
          │                                   │
┌─ C. 수강신청 전략 (앱 실행 중) ───────────────────────────────────────────────┐
│ 경쟁률 정리 → 성공 확률 p_x(k) → 손실 w_x → 신청 순서(할당 문제)              │
│ → 플랜 B 결정 트리 → 몬테카를로 시뮬레이션 → 대기순번 판단 → LLM 설명         │
│                                    ⇒ 순서표, 트리, 시뮬레이션 지표, 설명 문장  │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 단계 사이의 약속 (데이터 계약)

| 넘겨주는 것 | 만드는 곳 | 받는 곳 | 형태 | 핵심 내용 |
|---|---|---|---|---|
| `data/courses_<학기>.csv` | A부 6단계 | B부 전체, C부 1.2 | CSV (커밋함) | `Course` 한 줄씩: 키, 시간 조각, 건물, 이수구분, 수업 형태, 수강 대상·전공 인정 학과, 평가 비율 |
| `data/profiles_<학기>.jsonl` | A부 2.5 | B부 8 | JSON Lines (커밋함) | 분반 한 줄씩: 강의 방식, 과제 목록, 시험 형태, 출석 규정, 교재, 특이사항, 근거 인용, 추출 출처 |
| `data/buildings.csv` | 손으로 입력 | B부 3.8 | CSV (커밋함) | 건물 번호, 이름, 캠퍼스, 좌표 |
| `data/dept_alias.csv` | 손으로 입력 | B부 1.5 | CSV (커밋함) | 학과 이름 별칭 |
| `competition.csv` | A'부 | C부 1 | CSV (사용자 컴퓨터에만) | 키, 정원, 신청 인원, 출처 |
| 특징표 | B부 4 | B부 5–7 | `pd.DataFrame` (메모리) | 시간표 한 줄 = 특징 벡터 f(T) |
| 정렬된 시간표 집합 𝒯_f, 목표 T* | B부 5–6 | C부 3, 5, 6 | `pd.DataFrame` + 선택 행 | 순위 rank(T) |
| 전략 결과 | C부 4–7 | C부 8, 화면 | JSON | 순서표, 트리, 지표 |

모든 단계의 공통 키는 **`학수번호-분반`** (예: `BIZ2021-01`)이다.

## 실행 방식

| 언제 | 무엇 | 명령 / 동작 |
|---|---|---|
| 학기당 1회 (개발자) | A부 build | `uv run python -m kkul.loader.build --year 2026 --term 20` |
| 앱 시작 | courses.csv 읽기 | `st.cache_data`로 한 번만 |
| [시간표 만들기] 클릭 | B부 1–4 | 결과 특징표를 `st.session_state`에 저장 |
| 필터·정렬 변경 | B부 5–7 | 저장된 특징표로 즉시 다시 계산 |
| 시간표 하나 선택 | B부 8 | profiles.jsonl에서 해당 분반만 읽어 상세 보기 (LLM 호출 없음, 종합 요약만 선택) |
| 캡처 업로드 | A'부 | LLM 읽기 → 사용자 확인 → competition.csv |
| [전략 짜기] 클릭 | C부 1–8 | 시뮬레이션은 시드 고정, 결과 캐시 |

  timetable/              # B부 (김지후)

    explorer.py           #   필터·정렬·묶기

    probability.py        #   경쟁률, 성공 확률
    fallback.py           #   손실, Next, 결정 트리

기획서의 파일 이름과의 대응: `loader.py` → `kkul/loader/`, `scheduler.py`·`analyzer.py` → `kkul/timetable/`, `strategy.py` → `kkul/strategy/`. 기획서의 함수 약속(`load_courses`, `generate`, `analyze`, `plan`, `explain`)은 각 부의 함수 약속으로 세분화했다.

# A부. 데이터 파이프라인

전자시간표 공개 데이터는 학기당 한 번 자동으로 받아 CSV로 만들고, 정원·경쟁률은 사용자가 화면 캡처를 올리면 LLM이 읽어 넣는다.

- 담당: 이유찬 (`loader/`), 김지후 (캡처 읽기 `capture.py`의 LLM 부분)
- 앱은 학교 서버에 접속하지 않는다. 미리 만든 CSV와 사용자가 올린 캡처만 쓴다.

### 전체 흐름

```
[학기당 1회, build]                                         [사용할 때, app]
0 코드 목록 → 1 과목 목록 → 2 수업계획서 → 3 파싱 → 4 정규화·병합 → 5 검증 → 6 저장
                                                                         ↓
                                         courses.csv ──→ 시간표 생성·분석
                                                              ↑
                  사용자 캡처 이미지 → LLM 읽기 → 확인·수정 → competition.csv → 신청 순서
```

### 데이터 출처와 받아오는 항목

| 출처 (로그인 불필요) | 요청 | 받는 항목 | 확인 상태 |
|---|---|---|---|
| 학사-전공과목 | `E_NHSSU900020M/selectMain.do` | 학수번호, 분반, 과목명(국·영), 학점(시수), 교수, 요일·시간·강의실, 이수구분, 수업 형태, 국제어수업, 비고 | 확인 (Python에서 108개) |
| 전체과목 검색 | `E_NHSSU900070M/selectMain.do` | 위 항목 + **수강 대상 학과**(`GYJUNINJ_HAKGWA`), 개설 학부 | 응답 확인, 요청 본문 미확인 |
| 수업계획서 | `E_NHSSU900011P/selectMain0.do` | **평가 비율**(출석·과제·중간·기말·평소·발표·기타), 사용 언어, 선수과목, 예습·복습 시간, 수업 방식(강의·토론·실험 등), 계획서 입력 방식 | 응답 확인, 요청 본문 미확인 |
| 학사-교양 | 미확인 | 교양 과목 목록 | 미확인 |
| 단과대·학과 코드 | `E_NHSSU900020M/selectBizType03.do`, `04.do` | 단과대 코드, 학과 코드 | 응답 확인, 요청 본문 미확인 |

받지 않는 것: 정원, 신청 인원 (공개 화면에 없음). 수업계획서의 교수 개인 연락처(`HOME_TEL`, `HANDPHONE_NO`, `EMAIL`, `OFFICE_TEL`)는 응답에 섞여 오지만 저장하지 않는다.

### 단계별 계획

#### 0. 코드 목록 (`skku_client.py`)
- 단과대 → 학과 코드 목록을 받아 `(캠퍼스, 학과코드, 학과명)`을 만든다.
- 범위: 1차는 우리가 쓸 학과 몇 개 + 교양. 잘 되면 전체로 넓힌다.

#### 1. 과목 목록 (`skku_client.py`)
- 학과별로 `900020M`을 호출한다. (v2 스크립트의 세션·헤더 그대로)
- 수강 대상 학과는 `900070M`에서 받는다. 학수번호 단위로 조회되므로, 1단계에서 나온 학수번호마다 한 번씩 호출한다. 넓은 조건(빈 검색어 등)으로 한 번에 받을 수 있는지 먼저 확인하고, 되면 그 방법을 쓴다.
- 공통 규칙: 요청 간 1초 휴식, 503이면 2·4·8초 간격으로 3번까지 재시도, 응답 원문은 `data/raw/<학기>/<종류>/<키>.ssv`에 저장하고 있으면 다시 요청하지 않는다.

#### 2. 수업계획서 (`skku_client.py`)
- 분반마다 한 번씩 호출해야 해서 요청 수가 가장 많다. 경영학과만 해도 108번, 1초 간격이면 약 2분.
- 1차 범위에서만 받고, 원문 캐시로 중단·재개가 가능하게 한다.
- 주의: 확인한 BIZ2021-01은 계획서를 PDF로 올린 과목이라 **평가 비율 칸이 비어 있었다.** 웹 양식으로 입력한 과목만 비율이 채워진다. 실제로 몇 %의 과목에 비율이 있는지 1주차에 측정한다. 빈 과목은 2.5단계의 PDF 추출로 채운다.

#### 2.5 수업계획서 PDF → LLM 구조화 추출 (`syllabus.py`, `extract_syllabus.py`)

**① PDF 수집 (로그인 불필요, 브라우저·Python에서 확인함)**

| 순서 | 요청 | 보내는 값 | 받는 값 |
|---|---|---|---|
| 1 | `E_NHSSU900011P/selectFile2.do` | `GAESUL_YEAR`, `GAESUL_TERM`, `HAKSU_NO`, `BUNBAN` | `BIZ_PLN_FILE_ID` (없으면 PDF 없음) |
| 2 | `E_NAttachFile/selectAttachFiles.do` | `FILE_ID` = 위 값 | `FILE_NM`, `DOWNLOAD_FILE_ID`, `FILE_SEQ` |
| 3 | `E_Nsystem/fileDownload.do?attachFileId=…&sequenceNumber=…` (GET) | | PDF 원본 |

- 예: BIZ2021-01 → `BIZ2021 Syllabus 2026-Fall.pdf` (115KB, 2쪽, Word로 만든 텍스트 PDF)
- 요청 간 1초, 원본은 `data/raw/syllabus/<키>.pdf`에 캐시 (커밋하지 않음)
- 테스트 스크립트: `syllabus_fetch.py`

**② 텍스트 추출**
- `pypdf`로 쪽별 텍스트를 뽑는다. 글자가 200자 미만이면 `scanned_or_empty`로 표시하고 이번 범위에서는 건너뛴다 (나중에 OCR 또는 LLM 비전).
- 웹 양식으로 입력된 계획서는 2단계 응답의 필드(평가 비율, 수업 방식, 교재 등)를 같은 스키마로 옮겨 LLM 없이 처리한다.

**③ LLM 구조화 추출**
텍스트를 보내고 아래 JSON 스키마로만 답하게 한다 (`llm.py`의 JSON 모드 + 스키마 검증). 계획서에 없는 항목은 `null`.

```json
{
  "eval": {"attend": 10, "homework": 20, "quiz": 0, "mid": 30, "final": 30,
           "presentation": 0, "project": 10, "etc": 0},
  "exams": {"count": 2, "types": ["서술형"], "open_book": false, "weeks": [8, 15]},
  "assignments": [{"name": "팀 프로젝트", "team": true, "count": 1, "weeks": [10, 14]},
                  {"name": "주간 퀴즈", "team": false, "count": 12, "weeks": null}],
  "teamwork": true,
  "attendance": {"strict": true, "rule": "결석 4회 이상 F"},
  "lecture_style": ["강의", "사례 토론"],
  "language": "영어",
  "materials": ["Managerial Accounting (교재명)"],
  "prerequisite": "회계원리",
  "workload_level": 4,
  "notes": ["모듈 강좌: 학기 전반부 6주만 진행"],
  "evidence": {"eval": "Midterm 30%, Final 30% ...", "teamwork": "team project ...",
               "attendance": "...", "workload_level": "weekly quiz ..."}
}
```

- `workload_level`(1–5)은 LLM이 판단하되, 판단 근거 문장을 `evidence`에 반드시 넣게 한다. 기준을 프롬프트에 적는다: 1 = 시험만, 3 = 정기 과제 + 시험, 5 = 주간 과제·팀 프로젝트·발표가 겹침.

**④ 검증 (코드)**
| 검사 | 실패 시 |
|---|---|
| 스키마·자료형 | 그 분반 추출 전체 폐기 → 빈칸 |
| 평가 비율 합 = 100 (±1), 각 0–100 | `eval`만 폐기 |
| 시험·과제 주차 1–16 | 해당 주차만 폐기 |
| **근거 인용이 원문에 실제로 있는지** (공백 정규화 후 부분 문자열 검사) | 근거 없는 항목 폐기 |
| 웹 양식 값이 있으면 웹 값과 비교 | 웹 값 사용, 차이를 로그에 남김 |

# B부. 시간표 생성·탐색

겹치지 않는 시간표를 한꺼번에 만든 뒤, 사용자가 검색 필터처럼 **조건으로 거르고 원하는 우선순위로 정렬**해서 고른다. 각 조건은 아래 수학적 정의로 계산한다.

- 담당: 김지후 (`kkul/timetable/`)
- 입력: `courses.csv` (A부 결과), `buildings.csv` (동선용)
- 출력: 시간표 특징표(한 줄 = 시간표 하나) → 필터·정렬 결과

### 전체 흐름

```
사용자 정보 (소속 학과, 복수·부전공) + 과목 선택 + 꼭 지킬 조건
  → 0 수강 자격 거르기 + 전공 인정 표시
  → 1 후보 거르기
  → 2 같은 시간 분반 묶기
  → 3 조합 생성 (단조 조건으로 가지치기)
  → 4 특징 계산 → 특징표 (pandas DataFrame)
  ─────────────── 여기까지 [시간표 만들기] 버튼 한 번 ───────────────
  → 5 필터 (범위 조건의 교집합)       ← 사용자가 바꿀 때마다 즉시 다시 계산
  → 6 우선순위 정렬 (구간화한 사전식 순서)
  → 7 같은 시간 모양 묶어 보여주기
  ─────────────── 시간표 하나를 누르면 ───────────────
  → 8 상세 보기 (과목 카드, 주차별 부담, 선택 시 LLM 종합 코멘트)
```

### 1. 기본 정의

#### 시간
- 시각은 자정부터의 **분**으로 쓴다. 예: 10:30 → 630
- 요일 집합 D = {0, 1, 2, 3, 4, 5} (월–토), 평일 W = {0, 1, 2, 3, 4}

#### 분반과 시간표
- 분반 x는 수업 조각들의 집합이다. 각 조각은 (요일 d, 시작 s, 끝 e, 건물 b)
  - 예: BIZ2021-01 = {(1, 720, 795, 33), (3, 810, 885, 33)}
- 시간표 T는 듣기로 한 과목마다 분반 하나씩 고른 집합이다.
- 요일 d의 수업 조각을 시작 시각순으로 정렬한 것을

$$A_d(T) = \big((s_{d,1}, e_{d,1}, b_{d,1}), \dots, (s_{d,n_d}, e_{d,n_d}, b_{d,n_d})\big),\quad s_{d,1} < s_{d,2} < \dots$$

  로 쓰고, n_d는 그날 수업 조각 수다. 수업이 있는 요일 집합을 D⁺(T) = { d : n_d > 0 }로 쓴다.

#### 간격
같은 날 연이은 두 수업 사이 간격(쉬는 시간 또는 공강):

$$g_{d,i} = s_{d,i+1} - e_{d,i}, \qquad i = 1, \dots, n_d - 1$$

#### 비트마스크 표현 (구현용)
하루를 5분 칸 288개로 나눈다. 분반 x의 요일 d 마스크:

$$B_d(x) = \sum_{(d,s,e)\in x} \ \sum_{k=\lfloor s/5 \rfloor}^{\lceil e/5 \rceil - 1} 2^{k}$$

시간표의 마스크는 분반 마스크의 비트 OR: B_d(T) = ⋁_{x∈T} B_d(x)

### 1.5 수강 자격과 전공 인정 (`timetable/eligibility.py`)

#### 데이터에 있는 두 가지 학과 정보
| 필드 | 출처 | 의미 (추정) | 처리 |
|---|---|---|---|
| `restricted_depts` (`SUGANGDAESANG_HAKGWA`) | 수업계획서 | 수강 대상 학과: 이 학과만 들을 수 있음 | **자동 제외** |
| `major_depts` (`GYJUNINJ_HAKGWA`) | 전체과목 검색 | 이 학과의 전공으로 인정됨 (예: "경영학과, 자유전공계열") | **표시 + 선택 필터** |

주의: 두 필드의 정확한 의미는 화면 표기로 추정한 것이다. 확인한 BIZ2021-01은 `restricted_depts`가 비어 있었고 `major_depts`만 있었다. `major_depts`를 수강 제한으로 잘못 쓰면 다른 학과도 들을 수 있는 전공·교양 과목을 지워 버리므로, 1주차에 여러 과목을 보고 의미를 확정한다. 확정 전까지는 `major_depts`로는 제외하지 않는다.

#### 사용자 정보
- 소속 학과 u₀, 복수·부전공 학과 목록 U = {u₀, u₁, …}
- 사이드바 첫 칸에서 고르고(학과 목록은 A부 0단계의 학과 코드 목록), 브라우저에 기억해 둔다.

#### 정의
학과 이름은 비교 전에 정규화한다: 공백 제거, "학과/학부/전공" 접미사 통일, 별칭 표(`dept_alias.csv`, 예: "경영학과" = "경영학") 적용. 정규화 함수를 ν라 한다.

- **수강 가능**:

$$\text{eligible}(x, U) = \begin{cases} \text{참} & R_x = \varnothing \ (\text{제한 정보 없음}) \\ \exists\, u \in U:\ \nu(u) \in \nu(R_x) & \text{그 외} \end{cases}$$

  R_x = 분반 x의 `restricted_depts`. eligible이 거짓인 분반은 1단계 전에 후보에서 뺀다.

- **전공 인정**:

$$\text{major}(x, U) = \exists\, u \in U:\ \nu(u) \in \nu(J_x)$$

  J_x = `major_depts`. 결과 카드에서 과목마다 `내 전공 인정` / `타과 과목` 배지로 보여준다.

- 시간표 단위로는 전공 인정 학점을 센다: C_major(T) = Σ_{x∈T} c_x · 1[major(x, U)]. 특징표에 열로 넣어 필터(`전공 학점 ≥ 9`)와 정렬에 쓸 수 있다.

#### 화면 동작
- 담은 과목의 분반이 자격 때문에 전부 빠지면 바로 알린다: "재무관리 3개 분반 모두 수강 대상이 경영학과로 제한돼 있어요."
- 토글 `수강 대상 아닌 과목도 보기`: 켜면 제외했던 분반을 다시 넣고 빨간 `수강 대상 아님` 배지를 붙인다. 데이터가 틀렸거나 학과 승인으로 들을 수 있는 경우를 위한 출구다.
- 체크박스 `내 전공으로 인정되는 과목만`: 끄는 게 기본.

### 2. 겹침 (꼭 지켜야 함)

두 분반 x, y가 겹친다는 것은

$$\exists\, d \in D:\ B_d(x) \wedge B_d(y) \neq 0$$

(구간으로 쓰면 같은 요일의 두 조각에 대해 s₁ < e₂ 이고 s₂ < e₁)

시간표 T가 가능하다 ⇔ T 안의 어떤 두 분반도 겹치지 않는다. 가능한 시간표 전체를 𝒯라 한다.

### 3. 조건(특징)의 수학적 정의 (`timetable/analyzer.py`)

기준값 τ는 모두 설정에서 바꿀 수 있다. 1[조건]은 조건이 참이면 1, 거짓이면 0.

#### 3.1 아침수업
- 기준: τ_m = 540 (9:00), τ_e = 630 (10:30)
- 9시 수업이 있는 요일 수 (하루에 9시 시작 수업은 보통 하나라서 요일 단위로 센다):

$$M(T) = \sum_{d \in D^+} \mathbb{1}[\,s_{d,1} \le \tau_m\,]$$

- 이른 수업 요일 수 E(T): 같은 식에서 τ_m 대신 τ_e
- **과도한 아침수업 = 연속**: 9시 수업 요일 집합 D_m = { d : s_{d,1} ≤ τ_m } 안에서 가장 길게 이어진 요일 수

$$M_{\text{streak}}(T) = \max \{\, k : \exists\, d,\ \{d, d{+}1, \dots, d{+}k{-}1\} \subseteq D_m \,\}$$

#### 3.2 공강과 슈퍼공강
- 기준: τ_g = 60분 (이보다 짧으면 쉬는 시간, 즉 연강), τ_s = 180분 (슈퍼공강)
- 슈퍼공강 횟수:

$$S(T) = \sum_{d} \sum_{i} \mathbb{1}[\,g_{d,i} \ge \tau_s\,]$$

- 주간 공강 총합 (연강 쉬는 시간은 빼고):

$$G(T) = \sum_{d} \sum_{i} g_{d,i}\, \mathbb{1}[\,g_{d,i} \ge \tau_g\,]$$

- 가장 긴 공강: G_max(T) = max g_{d,i}

#### 3.3 연강 (한 번에 이어 듣는 시간)
간격이 τ_g보다 짧은 수업끼리 하나의 **덩어리**로 묶는다. 요일 d의 덩어리 경계는 g_{d,i} ≥ τ_g인 곳이다. 덩어리 k가 수업 i부터 j까지면 길이는 e_{d,j} − s_{d,i}.

$$L(T) = \max_{d,\ \text{덩어리}\ k} \big(e_{d,j_k} - s_{d,i_k}\big)$$

#### 3.4 우주공강
$$F(T) = \big|\, W \setminus D^+(T) \,\big|$$

어느 요일이 비는지(F_set = W ∖ D⁺)도 함께 저장한다.

#### 3.5 하루 체류시간
등교한 날 첫 수업 시작부터 마지막 수업 끝까지의 평균:

$$H(T) = \frac{1}{|D^+|} \sum_{d \in D^+} \big(e_{d,n_d} - s_{d,1}\big)$$

최대값 H_max도 같이 저장한다.

#### 3.6 점심시간
점심 창 Λ = [690, 810) (11:30–13:30), 필요 시간 τ_ℓ = 45분. 요일 d의 점심 창 안에서 수업이 없는 가장 긴 연속 구간 길이를 ℓ_d라 하면 (비트마스크에서 창 안의 연속 0 비트 최대 길이 × 5분)

$$P(T) = \sum_{d \in D^+} \mathbb{1}[\,\ell_d \ge \tau_\ell\,]$$

#### 3.7 야간 수업
$$N(T) = \sum_{d} \sum_{i} \mathbb{1}[\,s_{d,i} \ge 1080\,] \quad (18{:}00)$$

#### 3.8 동선
- 건물 b의 좌표 p_b (`buildings.csv`), 걷는 속도 v = 70 m/분, 언덕 보정 ρ (명륜 1.3, 직접 걸어 보고 조정)
- 연이은 두 수업 사이 이동 시간:

$$t_{d,i} = \begin{cases} 0 & b_{d,i} = b_{d,i+1} \\[2pt] \rho \cdot \dfrac{\lVert p_{b_{d,i}} - p_{b_{d,i+1}} \rVert}{v} & \text{같은 캠퍼스} \\[6pt] t_{\text{셔틀}} & \text{다른 캠퍼스} \end{cases}$$

- 좌표는 위경도를 캠퍼스 기준 평면 좌표(미터)로 바꿔 유클리드 거리를 쓴다. 캠퍼스 안 거리가 짧아 오차는 무시할 만하다.
- **지각 위험** (이동 시간이 간격보다 긴 경우):

$$R(T) = \sum_{d} \sum_{i} \mathbb{1}[\,t_{d,i} > g_{d,i}\,]$$

- 주간 이동 시간: V(T) = Σ_d Σ_i t_{d,i} · 1[g_{d,i} < τ_g] (공강이 긴 이동은 서두를 필요가 없어 뺀다)
- 온라인 수업 조각은 동선 계산에서 뺀다. 좌표가 없는 건물이 끼면 그 이동은 "알 수 없음"으로 세고 화면에 표시한다.

#### 3.9 학점과 평가 비율
- 총 학점: C(T) = Σ_{x∈T} c_x
- 시험 비중(학점 가중 평균), 평가 비율 데이터가 있는 과목 집합 K만 쓴다:

$$X(T) = \frac{\sum_{x \in K} c_x\,(\text{mid}_x + \text{final}_x)}{\sum_{x \in K} c_x}, \qquad \text{coverage} = \frac{\sum_{x\in K} c_x}{C(T)}$$

  coverage가 낮으면(예: 50% 미만) 화면에 "평가 정보 부족"을 표시한다.
- 같은 방식으로 과제 비중 Y(T)(과제), 출석 비중 Z(T)(출석)도 학점 가중 평균으로 계산한다.
- 평가 비율이 없는 과목은 0으로 채우지 않는다. 0으로 채우면 "시험 0%"로 보여 시험 비중 필터를 잘못 통과하기 때문이다.

#### 3.10 평가 비율 보여주기
- **과목 고를 때** (사이드바 검색 결과): 과목마다 평가 비율 가로 막대 하나. 출석·과제·중간·기말·발표·기타를 색으로 나눠 100%를 채운다. 비율이 없으면 `평가 비율 미입력 (계획서 PDF)`이라고 표시한다.
- **결과 카드** (시간표마다): 
  - 시간표 전체 막대: X, Y, Z 학점 가중 평균과 coverage (`5과목 중 3과목 기준`)
  - 과목 목록에 과목별 작은 막대와 `내 전공 인정` 배지
- **필터**: `시험 비중 최대 [50]%`. 비율 없는 과목이 섞인 시간표 처리는 토글 `평가 정보 없는 과목 포함 시간표도 보기`로 고른다 (기본 켬). 끄면 coverage = 100%인 시간표만 남는다.
- **정렬**: 시험 비중 낮은 순, 과제 비중 낮은 순 등을 정렬 조건 목록에 추가한다.

#### 3.11 계획서에서 나온 학기 부담 특징 (A부 2.5 결과 사용)
값이 없는 과목(None)은 계산에서 빼고, 3.9처럼 coverage를 함께 저장한다.

- **팀플 과목 수**: Q(T) = Σ_{x∈T} 1[teamwork_x = 참]
- **출석 엄격 과목 수**: A_s(T) = Σ_{x∈T} 1[attendance_strict_x = 참]
- **평균 과제 부담** (학점 가중, 값이 있는 과목 집합 K_w):

$$\bar W(T) = \frac{\sum_{x \in K_w} c_x \cdot \text{workload}_x}{\sum_{x \in K_w} c_x}$$

- **주차별 부담**: 학기 주차 w = 1, …, 16마다 시험은 α, 과제·발표 마감은 β만큼 더한다 (기본 α = 2, β = 1).

$$\text{load}_w(T) = \sum_{x \in T} \Big(\alpha\, \mathbb 1[w \in \text{exam\_weeks}_x] + \beta\, \mathbb 1[w \in \text{deadline\_weeks}_x]\Big)$$

- **가장 바쁜 주의 부담**: K(T) = max_w load_w(T)
- **몰리는 주 수**: J(T) = |{ w : load_w(T) ≥ θ }| (기본 θ = 4, 예: 시험 2개가 같은 주)

화면: 필터 `팀플 최대 [1]과목`, `몰리는 주 최대 [1]주`, 정렬 `과제 부담 낮은 순`, `가장 바쁜 주 부담 낮은 순`.

중간·기말 주차는 대부분 과목이 같아서 K(T)는 시험 기간에 거의 정해진다. 그래서 시험 기간을 뺀 주차만으로 계산한 K′(T)도 함께 저장해, "학기 중에 과제가 몰리는 주"를 따로 볼 수 있게 한다.

#### 특징 벡터
시간표 하나를 다음 벡터로 나타내고, 이것이 특징표의 한 줄이 된다.

$$\mathbf{f}(T) = \big(M, E, M_{\text{streak}}, S, G, G_{\max}, L, F, H, H_{\max}, P, N, R, V, C, C_{\text{major}}, X, Y, Z, \text{coverage}, Q, A_s, \bar W, K, K', J\big)$$

### 4. 생성과 가지치기 (`timetable/scheduler.py`)

#### 4.1 백트래킹
과목을 분반(시간 묶음) 수가 적은 순으로 정렬하고, 한 과목씩 분반을 넣으며 겹치면 그 가지를 버린다. 최악의 경우 탐색 공간 크기는

$$|\mathcal{T}| \le \prod_{k=1}^{K} n_k \quad (n_k = \text{과목 } k\text{의 분반 묶음 수})$$

6과목 × 4묶음 = 4,096, 8과목 × 8묶음 = 약 1,677만.

#### 4.2 같은 시간 분반 묶기
두 분반 x, y의 모든 요일 마스크와 건물이 같으면 같은 묶음으로 본다. 특징 벡터 f는 시간과 건물에만 의존하므로 묶음 안 분반들은 f가 같다. 따라서 묶음 단위로 생성하고 마지막에 펼쳐도 결과가 같다.

#### 4.3 단조 조건으로 가지치기
부분 시간표 T′에 분반을 더해 T ⊇ T′가 될 때, 어떤 특징 f가

- **단조 증가** (f(T′) ≤ f(T)): 필터 상한 f ≤ u가 있고 이미 f(T′) > u이면, 이 가지에서 나오는 모든 시간표가 필터에 걸린다 → 가지를 버려도 결과가 바뀌지 않는다.
- **단조 감소** (f(T′) ≥ f(T)): 필터 하한 f ≥ l이 있고 이미 f(T′) < l이면 같은 이유로 버린다.

| 특징 | 수업을 더하면 | 가지치기 사용 |
|---|---|---|
| M, E (아침 요일 수), N (야간), C (학점), C_major (전공 학점) | 늘거나 같음 (단조 증가) | 상한 필터 |
| X, Y, Z (평가 비율 평균), W̄ (평균 과제 부담) | 평균이라 오르내림 | **사용 불가** → 생성 뒤 필터 |
| Q (팀플 수), A_s (출석 엄격), K, K′ (가장 바쁜 주), J (몰리는 주 수) | 과목을 더하면 각 주 부담이 늘기만 하므로 늘거나 같음 (단조 증가) | 상한 필터 |
| F (우주공강) | 줄거나 같음 (단조 감소) | 하한 필터 |
| H_max (최대 체류시간), L (최장 연강) | 늘거나 같음 | 상한 필터 |
| S (슈퍼공강), G (공강 합), R (지각 위험), P (점심) | 사이에 수업이 들어가면 줄 수도 있음 | **사용 불가** → 생성 뒤 필터 |

(예: 10시·15시 수업 사이에 13시 수업이 들어오면 슈퍼공강이 사라진다. 지각 위험 쌍도 사이에 수업이 끼면 바뀐다.)

안전장치: 결과 5만 개 또는 2초를 넘으면 멈추고 "과목이나 꼭 지킬 조건을 더 정해 주세요"를 표시한다.

### 5. 필터 = 범위 조건의 교집합 (`timetable/explorer.py`)

사용자가 특징 j마다 범위 [l_j, u_j]를 정한다 (정하지 않으면 [−∞, ∞]). 필터 결과는

$$\mathcal{T}_{\text{filter}} = \{\, T \in \mathcal{T} \ :\ l_j \le f_j(T) \le u_j \ \ \forall j \,\}$$

요일 체크박스(예: 금요일 비우기)는 F_set ∋ 금 조건으로 같은 방식으로 더한다.

**남는 개수 미리 보기**: 특징 j의 범위만 바꿨을 때 남는 개수는, j를 뺀 나머지 조건만 적용한 집합에서 j 조건을 세면 된다.

$$\text{count}_j(l', u') = \big|\{\, T : l' \le f_j(T) \le u',\ \ l_k \le f_k(T) \le u_k\ \ \forall k \ne j \,\}\big|$$

결과가 0개일 때는 각 j마다 범위를 한 칸 넓혔을 때의 count_j를 계산해 가장 많이 늘어나는 조건을 제안한다. 예: "9시 수업 최대를 1→2로 올리면 12개가 생겨요"

구현은 특징표에 pandas 조건식을 적용하는 것이다. 수천–수만 행이면 즉시 끝난다.

### 6. 우선순위 정렬 = 구간화한 사전식 순서

사용자가 정렬 조건을 순서대로 고른다: (j₁, σ₁), (j₂, σ₂), …, (j_r, σ_r). σ = +1이면 작은 값이 먼저, −1이면 큰 값이 먼저.

#### 6.1 구간화
연속값은 정렬할 때만 폭 δ_j인 구간으로 묶는다 (정수값은 δ = 1, 즉 그대로).

$$q_j(T) = \sigma_j \cdot \left\lfloor \frac{f_j(T)}{\delta_j} \right\rfloor$$

기본 폭: 공강 분 30, 체류시간 60, 이동 시간 10, 시험 비중 10%p.

#### 6.2 사전식 순서
정렬 키 벡터 Q(T) = (q_{j₁}(T), …, q_{j_r}(T))에 대해

$$T \prec T' \iff \exists\, k:\ q_{j_i}(T) = q_{j_i}(T')\ \ (i < k)\ \ \text{그리고}\ \ q_{j_k}(T) < q_{j_k}(T')$$

즉 1순위 구간이 같을 때만 2순위를 보고, 그것도 같으면 3순위를 본다. 모든 키가 같으면 시간표 번호로 순서를 고정해서 결과가 매번 같게 한다.

#### 6.3 구간화가 필요한 이유
구간화 없이 공강 분(G)을 1순위로 두면, 대부분 시간표의 G 값이 5분 단위로 서로 달라서 1순위만으로 순서가 다 결정되고 2순위 이하는 거의 쓰이지 않는다. δ = 30이면 "공강 합이 30분 안쪽으로 같은" 시간표끼리 묶여 다음 조건이 의미를 갖는다.

#### 6.4 성질 (발표용)
사전식 순서에서 1위인 시간표는 정렬에 쓴 조건들 기준으로 **파레토 최적**이다. 1위보다 모든 조건에서 나쁘지 않고 하나라도 더 좋은 시간표가 있다면, 그 시간표가 앞섰을 것이기 때문이다. (구간화하면 "구간 단위로" 파레토 최적이다.)

구현: `df.assign(**{f"q_{j}": ...}).sort_values(by=[...], kind="stable")`

### 7. 같은 시간 모양 묶기

두 시간표가 모든 요일 마스크가 같으면 같은 모양이다.

$$T \sim T' \iff B_d(T) = B_d(T')\ \ \forall d \in D$$

이 관계는 동치 관계라 시간표들을 그룹으로 나눈다. 같은 그룹은 시간 특징(M, S, F …)이 모두 같고 교수·분반·건물만 다르다. 정렬 결과에서 그룹마다 첫 시간표만 보이고 "같은 시간 모양 n개 더 보기"로 펼친다. 구현: 요일 마스크 6개를 튜플로 만들어 `groupby`.

같은 그룹 안에서는 교수·분반이 달라 계획서 특징(Q, W̄, K …)이 다를 수 있다. 펼쳤을 때 이 값들로 그룹 안 순서를 정한다.

# C부. 수강신청 전략

사용자가 고른 목표 시간표를 기준으로 **① 어떤 순서로 신청할지, ② 실패하면 무엇으로 갈아탈지, ③ 그 전략이 얼마나 잘 될지**를 계산한다. 숫자는 모두 코드가 계산하고, LLM은 결과를 문장으로 설명만 한다.

- 담당(제안): 이유찬 (`strategy/probability.py`, `strategy/order.py`, 화면), 김지후 (`strategy/fallback.py`, `strategy/simulate.py`, `explain`)
- 입력: 목표 시간표 T*, 필터·정렬을 마친 시간표 집합 𝒯_f (B부 결과), `competition.csv` (A부 캡처 입력) 또는 추정 경쟁률
- 출력: 신청 순서표, 플랜 B 결정 트리, 시뮬레이션 지표, LLM 설명

### 전체 흐름

```
목표 시간표 T* + 후보 시간표 집합 𝒯_f + 경쟁률
  → 1 경쟁률 정리 (캡처값 / 추정값)
  → 2 분반별 성공 확률 p_x(k)        (k = 몇 번째로 신청하는지)
  → 3 놓쳤을 때의 손실 w_x            (𝒯_f 재활용)
  → 4 신청 순서 최적화                 (할당 문제)
  → 5 플랜 B 결정 트리                 (𝒯_f 재활용)
  → 6 몬테카를로 시뮬레이션            (전략 평가·비교·민감도)
  → 7 대기순번 판단
  → 8 LLM 설명
```

### 1. 경쟁률 정리 (`strategy/probability.py`)

#### 1.1 캡처값이 있을 때
$$r_x = \frac{a_x}{c_x}$$

#### 1.2 캡처값이 없을 때: 인기도 추정
공개 데이터로 만든 특징 z_x로 경쟁률을 추정한다.

$$\hat r_x = r_0 \cdot \exp\Big(\sum_{j} \beta_j\, z_{x,j}\Big)$$

| 특징 z | 정의 | β 부호 (가정) |
|---|---|---|
| 분반 희소성 | 1 / (같은 과목 분반 수) | + (분반이 적으면 몰림) |
| 전공핵심 | 이수구분이 전공핵심이면 1 | + |
| 인기 시간대 | 10:30–15:00 수업 비율 | + |
| 아침·야간 | 9:00 이하 또는 18:00 이후 시작이면 1 | − |
| 대상 학과 수 | 전공 인정 학과 수 (log) | + |

- r₀, β는 손으로 정한 시작값이다. 캡처값이 쌓이면 log r_x = log r₀ + Σβ_j z_{x,j}를 최소제곱으로 맞춰 다시 정할 수 있다 (선형회귀).
- 화면에는 출처 배지를 붙인다: `캡처` / `추정`. 추정값은 회색으로 보여준다.

---

### 2. 성공 확률 모델: 몇 번째로 누르면 자리가 남아 있을까

#### 2.1 가정
- 수강신청이 열리는 순간을 t = 0으로 둔다.
- 나를 뺀 경쟁자 a_x − 1명은 서로 독립으로, 신청 시각 τ가 지수분포를 따른다고 가정한다. 대부분 처음 몇십 초 안에 몰리는 현상을 단순하게 표현한 것이다.

$$\Pr[\tau \le t] = F(t) = 1 - e^{-t/\mu}$$

  μ = 경쟁자 평균 신청 시각 (기본 30초)
- 나는 한 과목 신청에 Δ초 걸린다 (학수번호 입력, 확인 포함, 기본 5초). k번째 과목은 t_k = kΔ에 신청된다.

#### 2.2 성공 확률
내 앞에 신청한 경쟁자 수 N_k는 이항분포다.

$$N_k \sim \text{Binomial}\big(a_x - 1,\ F(t_k)\big)$$

정원 c_x 안에 들려면 앞선 사람이 c_x − 1명 이하여야 한다.

$$p_x(k) = \Pr[N_k \le c_x - 1] = \sum_{i=0}^{c_x-1} \binom{a_x-1}{i} F(t_k)^i \big(1-F(t_k)\big)^{a_x-1-i}$$

- 성질: k가 커질수록 F(t_k)가 커지므로 p_x(k)는 **감소**한다. a_x ≤ c_x이면 항상 p_x(k) = 1이다.
- 구현: `scipy.stats.binom.cdf(c - 1, a - 1, F(t_k))`

#### 2.3 미루면 잃는 확률
k번째에서 k+1번째로 밀리면 잃는 확률:

$$d_x(k) = p_x(k) - p_x(k+1) \ \ge 0$$

경쟁률이 높을수록 d_x가 처음 몇 칸에서 크고, 경쟁률이 낮으면 0에 가깝다. "먼저 눌러야 할 과목"은 d_x가 큰 과목이다.

#### 2.4 한계와 처리
μ, Δ, 경쟁자의 신청 순서는 실제 데이터가 없다. 그래서 결과는 **정확한 확률이 아니라 전략끼리 비교하는 상대 지표**로 보여주고, 6.4절 민감도 분석으로 가정이 바뀌어도 결론이 유지되는지 확인한다.

### 3. 놓쳤을 때의 손실 (`strategy/fallback.py`)

#### 3.1 시간표 효용
사용자는 점수 대신 우선순위 정렬을 쓰므로, 정렬 순위를 0–1 효용으로 바꾼다.

$$u(T) = 1 - \frac{\text{rank}(T) - 1}{|\mathcal T_f|}$$

1위 시간표는 u = 1. (사용자가 정한 순서를 그대로 쓰므로 새 가중치가 필요 없다.)

#### 3.2 분반을 놓쳤을 때 갈 수 있는 최선
분반 x만 실패했을 때 갈아탈 수 있는 가장 좋은 시간표:

$$\text{fb}(x) = \arg\max_{T \in \mathcal T_f,\ x \notin T} u(T)$$

#### 3.3 손실
$$w_x = \text{imp}_x \cdot \big(u(T^*) - u(\text{fb}(x))\big)$$

- fb(x)가 없으면 (x 없이 가능한 시간표가 하나도 없으면) u(fb(x)) = 0으로 두고, 꼭 들을 과목이면 imp_x를 크게 준다 (기본 꼭 들을 과목 3, 들으면 좋은 과목 1).
- 같은 과목의 다른 분반으로 쉽게 갈아탈 수 있으면 u(fb(x))가 u(T*)에 가까워서 w_x가 작다. 이것이 이전 계획의 "대체 불가성"을 수식으로 만든 것이다.
- 근사: 다른 분반은 성공했다고 보고 x 하나만 실패한 경우로 계산한다. 여러 개가 동시에 실패하는 경우는 5장 결정 트리와 6장 시뮬레이션이 다룬다.

### 4. 신청 순서 최적화 = 할당 문제 (`strategy/order.py`)

#### 4.1 목적함수
T*의 분반 n개를 위치 1…n에 하나씩 배치하는 순열 π를 고른다. 각 분반을 성공하면 손실을 피하므로, **피한 손실의 기댓값**을 최대화한다.

$$\max_{\pi}\ \sum_{x \in T^*} w_x \, p_x\big(\pi(x)\big)$$

#### 4.2 할당 문제로 풀기
목적함수가 분반별 항의 합이므로, 이는 n×n 행렬 V_{x,k} = w_x · p_x(k)에서 행(분반)과 열(위치)을 하나씩 짝짓는 **선형 할당 문제**다.

- 헝가리안 알고리즘으로 O(n³)에 최적해를 구한다: `scipy.optimize.linear_sum_assignment(V, maximize=True)`
- n ≤ 8이면 8! = 40,320개 순열을 전부 계산해 검산할 수 있다 (테스트용).

#### 4.3 직관 (발표용): 인접 교환 논리
위치 k, k+1에 있는 두 분반 x, y의 순서를 바꿨을 때 목적함수 변화는

$$\big[w_x p_x(k) + w_y p_y(k+1)\big] - \big[w_y p_y(k) + w_x p_x(k+1)\big] = w_x\, d_x(k) - w_y\, d_y(k)$$

따라서 **w_x · d_x(k)가 큰 쪽을 먼저** 누르는 것이 낫다. "중요하고(w), 미루면 확률이 많이 떨어지는(d)" 과목이 앞에 온다. 이전 계획의 "위험 점수 = 중요도 × 경쟁률 × 대체 불가성"을 이 식으로 정확하게 만든 것이다.

#### 4.4 출력
| 순서 | 분반 | 경쟁률 (출처) | 이 위치 성공 확률 | 놓치면 갈 곳 | 이유 태그 |
|---|---|---|---|---|---|
| 1 | 재무관리-02 | 2.1 (캡처) | 0.71 | 재무관리-05 (시간표 3위) | 경쟁 높음, 대체 적음 |
| 2 | … | | | | |

### 5. 플랜 B 결정 트리 (`strategy/fallback.py`)

#### 5.1 상태와 다음 목표
신청 도중의 상태를 (A, F)로 둔다. 이 상태에서 갈 수 있는 최선의 시간표:

$$\text{Next}(A, F) = \arg\max \{\, u(T) : T \in \mathcal T_f,\ A \subseteq T,\ T \cap F = \varnothing \,\}$$

- A ⊆ T: 이미 확보한 분반은 버리지 않는다 (기본값. 옵션으로 "확보한 분반 포기 허용"을 켤 수 있다).
- 다음에 신청할 분반은 Next(A, F) ∖ A이고, 그 안의 순서는 4장 할당을 남은 위치로 다시 푼다.
- Next가 없으면: 남은 과목으로 학점을 채우는 시간표를 조건을 풀어서 찾는다 (B부 5장 완화 제안 재사용).

#### 5.2 트리 만들기
모든 경우를 펼치면 2ⁿ개라서, **실패 확률 × 손실이 큰 분반 m개**(기본 m = 3)만 갈래를 만든다.

$$\text{위험도}(x) = \big(1 - p_x(\pi(x))\big) \cdot w_x$$

- 위험도 상위 m개 분반에서만 성공/실패로 갈라지고, 나머지는 성공으로 가정한다. 잎은 최대 2^m = 8개.
- 각 잎에 도착할 확률(갈래 확률의 곱)과 최종 시간표, 그 시간표의 특징 변화(예: "수요일 슈퍼공강 1개 생김")를 붙인다.

```
① 재무관리-02 (성공 71%)
   ├ 성공 → ② 투자론-01 …
   └ 실패 → 재무관리-05 즉시 신청 (성공 64%)  → 시간표 3위: 수 슈퍼공강 +1
            └ 실패 → 재무관리 제외, 마케팅전략-01 → 시간표 9위: 15학점
```

#### 5.3 실시간 모드
신청 당일 사용자가 각 분반 결과를 `성공 / 실패 / 대기 n번` 버튼으로 누르면, 앱이 Next(A, F)를 바로 다시 계산해 "다음에 누를 학수번호"를 크게 보여준다. 신청은 사용자가 직접 하고, 앱은 학교 사이트에 접속하지 않는다 (매크로·자동 신청 금지 규정 준수).

### 6. 몬테카를로 시뮬레이션 (`strategy/simulate.py`)

#### 6.1 한 번의 시뮬레이션
1. A = ∅, F = ∅, 클릭 수 k = 0
2. 다음에 신청할 분반 x를 정책(4장 순서 + 5장 Next)으로 고른다. k ← k + 1
3. 균등난수 U < p_x(k)이면 A ← A ∪ {x}, 아니면 F ← F ∪ {x}
4. 목표가 남아 있으면 2로. 끝나면 최종 시간표 T_end = A를 기록

#### 6.2 지표 (N = 10,000회)
| 지표 | 식 |
|---|---|
| 목표 시간표 확보 확률 | P̂(T_end = T*) |
| 상위 5개 안 확보 확률 | P̂(rank(T_end) ≤ 5) |
| 기대 효용 | (1/N) Σ u(T_end) |
| 최소 학점 달성 확률 | P̂(C(T_end) ≥ C_min) |
| 가장 자주 실패하는 분반 | 실패 횟수 최빈값 |

확률 추정치의 95% 신뢰구간은 정규근사로

$$\hat p \pm 1.96\sqrt{\frac{\hat p(1-\hat p)}{N}}$$

N = 10,000이면 폭이 최대 ±1%p라서 "약 42%"처럼 반올림해 보여주면 충분하다. 시드를 고정해 같은 입력이면 같은 결과가 나오게 한다.

#### 6.3 전략 비교 (발표용)
같은 난수로 세 정책을 돌려 비교한다 (공통 난수법: 차이만 비교하므로 분산이 줄어든다).

| 정책 | 설명 |
|---|---|
| 기본 | 학수번호 순서대로 신청, 플랜 B 없음 |
| 경쟁률 순 | 경쟁률 높은 순서, 플랜 B 없음 |
| 꿀시간표 | 4장 할당 순서 + 5장 플랜 B |

예상 결과 형태: "목표 시간표 확보 확률: 기본 28% → 경쟁률 순 37% → 꿀시간표 46%"

#### 6.4 민감도 분석
가정한 값을 바꿔 가며 결론이 유지되는지 본다.

- μ ∈ {10, 30, 60}초, Δ ∈ {3, 5, 10}초, 경쟁률 ±30%
- 확인할 것: ① 최적 순서가 바뀌는지, ② 정책 간 순위(꿀시간표 > 경쟁률 순 > 기본)가 유지되는지
- 순서가 시나리오마다 달라지면, 시나리오 평균 목적함수로 4장 할당을 다시 푼다 (강건한 선택):

$$\max_\pi\ \frac{1}{|\Theta|}\sum_{\theta \in \Theta} \sum_x w_x\, p_x^{(\theta)}\big(\pi(x)\big)$$

  평균이어도 여전히 분반별 합이라 같은 할당 문제로 풀린다.

### 7. 대기순번 판단

성균관대는 정원이 차면 대기순번이 부여되고, 같은 과목을 다시 신청하면 기존 대기순번이 삭제된다.

#### 7.1 대기로 들어갈 확률
대기 번호 q, 정원 c, 수강신청 변경 기간까지 한 사람이 빠질 확률 δ(기본 5%, 가정)라 하면 빠지는 인원 D ~ Binomial(c, δ)이고

$$P_{\text{wait}}(q) = \Pr[D \ge q] = 1 - \sum_{i=0}^{q-1} \binom{c}{i}\delta^i(1-\delta)^{c-i}$$

#### 7.2 기다릴지 갈아탈지
- 기다리기의 기대 효용: P_wait · u(T*) + (1 − P_wait) · u(나중 대안)
- 지금 갈아타기의 효용: u(Next(A, F ∪ {x}))
- 기다리기 쪽이 크면 "대기 유지, 이 과목 다시 누르지 마세요", 아니면 "대안 분반으로 이동"을 표시한다.
- 확인 필요: 대기 중에 같은 과목의 다른 분반을 신청할 수 있는지, 그때 대기가 유지되는지. 확인 전에는 다른 분반 신청 시 대기가 사라진다고 보수적으로 가정한다. δ도 실제 데이터가 없어 민감도 분석 대상이다.
