# 꿀시간표 프론트엔드 계획 (v1) — NiceGUI + API 계층

화면은 NiceGUI로, 백엔드 접근은 FastAPI API 계층으로 나눈다. 우리가 작성하는 코드는 전부 Python이다. 화면 코드는 `api/`만 부르고, 계산은 `kkul/`(백엔드 파이프라인 A·B·C부)이 한다.

- 담당(제안): 이유찬 `ui/` 화면 전체, 김지후 `api/service.py`와 백엔드 연결, `api/schemas.py`는 공동
- 관련 문서: [01_backend_pipeline.md](01_backend_pipeline.md)

## 원칙

1. **화면은 API만 안다.** `ui/`는 `kkul/`을 직접 import하지 않고 `api/service.py`만 부른다. 나중에 화면을 바꿔도 백엔드는 그대로다.
2. **약속은 `api/schemas.py`.** 요청·응답 형식(pydantic 모델)을 1주차에 먼저 정하고, 둘이 동시에 개발한다.
3. **목업 먼저.** 백엔드가 완성되기 전에는 `api/mock.py`가 같은 형식의 가짜 데이터를 돌려준다. 화면 개발이 백엔드를 기다리지 않는다.
4. **화면이 멈추지 않게.** 시간표 생성·시뮬레이션처럼 무거운 계산은 별도 프로세스(`run.cpu_bound`)에서 돌리고, 그동안 진행 표시를 보여준다.
5. **열 때 LLM을 기다리지 않는다.** LLM이 필요한 기능(자연어 필터, 종합 코멘트, 캡처 읽기, 전략 설명)은 버튼을 눌렀을 때만 호출한다. 키가 없으면 그 버튼을 숨긴다.

## 구조

```
main.py                  # ui.run(...) + API 라우트 등록, 저장소 비밀키(.env)
api/
  schemas.py             # 요청·응답 pydantic 모델 (공동, 1주차 확정)
  service.py             # 화면과 라우트가 함께 쓰는 함수: kkul/을 불러 schemas 형식으로 변환
  routes.py              # service 함수를 REST로 공개: /api/...  (자동 문서 /docs)
  mock.py                # 개발 초기 가짜 service (같은 함수 이름, 같은 반환 형식)
  store.py               # 세션별 서버 메모리 저장소 (큰 결과 보관)
ui/
  layout.py              # 공통 머리글, 단계 표시, 색상표
  pages/
    start.py             # /          1. 시작
    explore.py           # /explore   2. 시간표 찾기
    details.py           # /t/{id}    3. 상세 보기
    strategy.py          # /strategy  4. 수강신청 전략
    live.py              # /live      5. 실시간 모드
  components/
    timetable_grid.py    # 주간 시간표 격자
    filter_panel.py      # 필터 슬라이더·체크박스 + 남는 개수
    sort_editor.py       # 우선순위 정렬 편집기
    course_card.py       # 과목 카드 (평가 막대, 배지, 계획서 정보)
    eval_bar.py          # 평가 비율 막대
    charts.py            # 주차별 부담, 시뮬레이션 결과 (ui.echart)
    strategy_tree.py     # 플랜 B 트리 (ui.mermaid)
kkul/                    # 백엔드 (01_backend_pipeline.md)
```

**화면 → API 호출 방식**: 같은 서버 안이라 `ui/`는 `service.py` 함수를 바로 부른다 (HTTP를 거치지 않아 빠르다). `routes.py`는 똑같은 `service` 함수를 HTTP로도 열어 둔다. 그래서 `/docs`에서 API를 직접 시험해 볼 수 있고, 발표에서 "백엔드는 API로 공개되어 있다"를 보여줄 수 있다.

```python
# api/routes.py
@router.post("/timetables/{set_id}/query", response_model=QueryResult)
def query(set_id: str, req: QueryRequest):
    return service.query_timetables(set_id, req)

# ui/pages/explore.py
result = service.query_timetables(state.set_id, state.query)   # 같은 함수
```

## 상태 관리

| 무엇 | 어디에 | 이유 |
|---|---|---|
| 학과, 담은 과목, 꼭 지킬 조건, 필터, 정렬 순서, 고른 시간표 id | `app.storage.user` (브라우저별, 서버 저장) | 새로고침해도 유지. 작은 값만 |
| 생성된 시간표 집합(특징표 DataFrame, 수천–수만 행) | `api/store.py` 서버 메모리, `set_id`로 찾음 | 커서 브라우저 저장소에 못 넣음. 최근 20개만 보관(LRU), 30분 안 쓰면 삭제 |
| `courses.csv`, `profiles.jsonl` | 서버 시작 때 한 번 읽어 메모리에 | 모든 사용자가 같이 씀 |
| 캡처 이미지, competition 결과 | 서버 메모리 `set_id` 아래 | 사용자 컴퓨터 밖으로 보내지 않음, 저장소에 커밋 안 함 |
| 화면 안의 일시적 값 (펼침 여부 등) | 컴포넌트 변수 | 저장할 필요 없음 |

## API 목록 (`api/schemas.py`)

| 메서드·경로 | 요청 | 응답 | 백엔드 |
|---|---|---|---|
| `GET /api/meta` | | 학기, 캠퍼스, 학과 목록 | A부 0단계 결과 |
| `GET /api/courses` | `q`, `dept`, `category` | `CourseSummary[]` (키, 이름, 교수, 시간, 학점, 평가 막대용 값, 배지) | A부 결과 |
| `POST /api/timetables/generate` | `GenerateRequest` (학과들, 담은 과목+꼭/선택, 꼭 지킬 조건, 학점 범위) | `{set_id, count, truncated, warnings[]}` | B부 1.5–4 |
| `POST /api/timetables/{set_id}/query` | `QueryRequest` (필터, 정렬, 구간 폭, 묶기 여부, 페이지) | `{total, items: TimetableCard[], counts: {필터별 남는 개수}, relax: [완화 제안]}` | B부 5–7 |
| `GET /api/timetables/{set_id}/{tt_id}` | | `TimetableDetail` (격자, 특징, 과목 카드, 주차별 부담, 몰리는 주) | B부 8.1–8.2 |
| `POST /api/timetables/{set_id}/{tt_id}/summary` | | `{text}` | B부 8.3 (LLM) |
| `POST /api/preferences/parse` | `{text}` | `{filters, sort, unclear[]}` | 자연어 → 필터 (LLM) |
| `POST /api/capture` | 이미지 여러 장 | `{rows: [{key, capacity, applied, ok, issue}]}` | A'부 (LLM) |
| `PUT /api/competition/{set_id}` | 사용자가 확인한 rows | `{saved}` | A'부 |
| `POST /api/strategy/{set_id}/{tt_id}` | `{mu, delta_t, drop, m}` | `StrategyResult` (순서표, 트리, 시뮬레이션, 정책 비교) | C부 1–7 |
| `POST /api/strategy/{set_id}/{tt_id}/explain` | | `{summary, per_course[], warnings[]}` | C부 8 (LLM) |
| `POST /api/strategy/{set_id}/next` | `{secured[], failed[], waiting: {key: q}}` | `{next_keys[], target_tt_id, wait_advice[]}` | C부 5.1, 7 |

핵심 응답 모델 예:

```python
class TimetableCard(BaseModel):
    tt_id: str
    sections: list[str]                 # ["BIZ2021-01", ...]
    grid: list[GridBlock]               # 격자에 그릴 블록
    tags: list[str]                     # ["금 우주공강", "슈퍼공강 없음", "9시 수업 1회"]
    features: dict[str, float | None]   # M, S, F, … (특징 벡터)
    group_size: int                     # 같은 시간 모양 개수

class GridBlock(BaseModel):
    key: str; name: str; day: int; start: int; end: int   # 분 단위
    room: str | None; color: int; online: bool; late_risk: bool
```

## 화면 설계

### 1. 시작 `/`

```
┌ 꿀시간표 ─────────────── ① 시작 ─ ② 찾기 ─ ③ 상세 ─ ④ 전략 ┐
│ 소속 학과 [경영학과 ▼]  복수·부전공 [+ 추가]   학점 [15 ━━●━ 18] │
├───────────────────────────────┬──────────────────────────────┤
│ 과목 검색 [재무관        🔍]   │ 담은 과목                     │
│ ┌ 재무관리 BUS2006 · 3학점 ┐   │ ● 재무관리   [꼭 ▼]  ✕        │
│ │ 분반 7개 · 전공핵심       │   │ ● 투자론     [꼭 ▼]  ✕        │
│ │ ▇▇▇▆▆▆ 평가 막대 [담기]  │   │ ● 마케팅전략 [선택 ▼] ✕       │
│ └──────────────────────────┘   │ 꼭 지킬 조건                   │
│                                │ ☐ 9시 수업 금지  ☐ 금요일 비우기 │
│                                │ ☐ 온라인 강의는 시간표에서 빼기  │
│                                │        [ 시간표 만들기 ]       │
└───────────────────────────────┴──────────────────────────────┘
```

- 학과 선택은 검색되는 선택 상자(`ui.select(with_input=True)`).
- 검색 결과 카드에 평가 막대, `내 전공 인정` / `수강 대상 아님` 배지, 분반 수.
- [시간표 만들기] → `generate` 호출, 진행 표시 → 끝나면 `/explore`로 이동. `truncated`면 "결과가 많아 일부만 만들었어요" 경고.
- 담은 과목 중 자격 때문에 분반이 다 빠진 과목은 빨간 안내.

### 2. 시간표 찾기 `/explore`

```
┌ 필터 ───────────────┬ 정렬: ① 9시 수업 적은 순 ↑↓✕ ② 슈퍼공강 적은 순 ↑↓✕ [+ 조건] ┐
│ 프리셋 [아침잠 많음▼] │ "말로 조건 정하기" [금요일 쉬고 팀플은 싫어…        ] [적용]   │
│ 9시 수업 최대 ●━ 1일 │ ─────────────────────────────────────────────────────── │
│   (37개)             │ 총 214개 · 같은 모양 묶음 58개                            │
│ 슈퍼공강 최대 ●━ 0번 │ ┌ 1 ───────────────┐ ┌ 2 ───────────────┐             │
│   (52개)             │ │ [작은 격자]        │ │ [작은 격자]        │             │
│ ☑ 우주공강 있는 것만  │ │ 금 우주공강 · 9시0 │ │ 슈퍼공강 없음      │             │
│ ☐ 금요일 비우기 (21) │ │ 팀플 1 · 몰리는 주0│ │ 동선 짧음          │             │
│ ☑ 지각 위험 없음     │ │ 같은 모양 3개 더 ▾ │ │ [상세] [비교 담기]  │             │
│ 시험 비중 최대 ━●50% │ └──────────────────┘ └──────────────────┘             │
│ 팀플 최대 ━● 1과목   │ … (20개씩 더 보기)                                       │
│ ▸ 더 보기 (점심, 야간…)│                                                          │
└──────────────────────┴──────────────────────────────────────────────────────────┘
```

- 필터를 움직이면 0.3초 동안 추가 입력이 없을 때 `query` 호출 (연속 호출 방지). 응답의 `counts`로 각 필터 옆 숫자를 갱신.
- 정렬 편집기: 조건 추가(선택 상자), 순서 ↑↓, 방향 토글, 삭제. 각 조건 옆에 구간 폭(⚙)은 펼쳐서만 보이게.
- "말로 조건 정하기"는 `preferences/parse` 결과를 필터·정렬 칸에 **채워 넣기만** 한다. 사용자가 확인하고 바꿀 수 있다. `unclear`가 있으면 칩으로 질문을 보여준다.
- 결과 0개: `relax` 제안을 버튼으로 보여준다. 예: [9시 수업 최대 1→2로 (12개)].
- 비교: 카드 2–3개를 "비교 담기"하면 아래에 특징을 나란히 보는 표가 열린다 (차이 나는 칸 강조).
- 카드 클릭 → `/t/{tt_id}`.

```
┌ ← 목록   시간표 #1  [이 시간표로 전략 짜기 →] ┐
│ [큰 주간 격자: 월–금(토) × 8:00–21:00]         │
│  온라인·시간 미정 과목: 경영통계(온라인)        │
├ 학기 부담 ──────────────────────────────────┤
│ [주차 1–16 쌓은 막대, 과목별 색]              │
│ ⚠ 10주차: 재무관리 팀 발표 + 투자론 과제 마감  │
├ 과목 ───────────────────────────────────────┤
│ ▸ 재무관리-02  토론형 · 영어 · 부담 ●●●●○      │
│   평가 막대 / 시험 2회(8, 15주) / 팀 프로젝트 │
│   출석: 결석 4회 이상 F  ⓘ 원문 보기          │
│ ▸ 투자론-01 …                                  │
├ 종합 코멘트 [이 시간표 요약해줘] ──────────────┤
└─────────────────────────────────────────────┘
```

- 과목 카드는 접었다 펴는 형태(`ui.expansion`). ⓘ를 누르면 근거 인용(`evidence`)과 출처(`웹 계획서` / `PDF 자동 추출`).
- 계획서 정보가 없는 과목은 "계획서 정보 없음"으로 칸을 비운다.
- 학기 부담 그래프는 `ui.echart` 쌓은 막대. 막대를 누르면 그 주의 시험·마감 목록.

### 4. 수강신청 전략 `/strategy`

```
┌ ① 경쟁률 입력 ──────────────────────────────────────┐
│ [캡처 올리기] 책가방·수강신청 화면 캡처 (여러 장)      │
│ 읽은 결과 (고칠 수 있음): 키 | 정원 | 신청 | 상태     │
│  BUS2006-02 | 40 | 63 | ✓      BIZ2021-01 | ? | ? | 추정 │
│                                        [확정]       │
├ ② 신청 순서 ─────────────────────────────────────────┤
│ 순서 | 분반 | 경쟁률(출처) | 성공 확률 막대 | 놓치면 | 이유 │
├ ③ 플랜 B ────────────────────────────────────────────┤
│ [트리 그림]  잎: 도착 확률 + [시간표 보기]             │
├ ④ 시뮬레이션 ────────────────────────────────────────┤
│ 목표 확보 46% (±1%) · 상위 5개 안 81% · 15학점 이상 97% │
│ [정책 비교 막대: 기본 / 경쟁률 순 / 꿀시간표]           │
│ 가정 바꿔 보기: μ [30초] Δ [5초] 빠지는 비율 [5%] [다시 계산] │
├ ⑤ 설명 [전략 설명 받기] ─────────────────────────────┤
└ [실시간 모드 열기 →] ───────────────────────────────┘
```

- 캡처 결과 표는 `ui.aggrid` 편집 가능 표. 이상값(정원 0, 키 없음)은 빨간 칸.
- 캡처가 없는 분반은 `추정` 회색 배지.
- 시뮬레이션은 시드 고정, 가정 값을 바꿔 [다시 계산]할 때만 다시 돌린다.

### 5. 실시간 모드 `/live` (휴대폰 우선)

```
┌──────────────────────┐
│  다음에 신청할 과목    │
│     BUS2006-02        │  ← 아주 큰 글씨, 누르면 복사
│     재무관리 (2/5)     │
│ [ 성공 ] [ 실패 ] [ 대기 ]│
│ 대기 번호 [  ]         │
│ ─────────────────     │
│ 확보: BIZ2021-01 ✓    │
│ 목표: 시간표 #1 → #3   │
│ 대기 조언: 투자론 23번 │
│  → 다시 누르지 마세요  │
└──────────────────────┘
```

- 버튼 하나 누를 때마다 `strategy/next` 호출, 다음 학수번호와 바뀐 목표 시간표를 보여준다.
- 학교 사이트에 접속하거나 자동으로 신청하지 않는다. 안내만 한다.
- 화면 폭 400px 기준으로 설계, 버튼은 손가락으로 누르기 쉬운 크기.

## 컴포넌트

| 컴포넌트 | 입력 | 구현 |
|---|---|---|
| `timetable_grid` | `GridBlock[]`, 크기(`mini`/`full`) | CSS 그리드: 열 = 요일, 행 = 5분 칸. 블록 위치는 Python이 계산 (`grid-row: (start−480)/5+1 / span (end−start)/5`). 과목별 색, 지각 위험 이동은 블록 사이 빨간 점선, 온라인 과목은 격자 아래 목록 |
| `filter_panel` | 현재 필터, `counts` | `ui.slider`, `ui.checkbox`, 숫자 배지. 자주 쓰는 6개만 보이고 나머지는 "더 보기" |
| `sort_editor` | 정렬 목록 | 행마다 조건 이름, ↑↓, 방향, ✕. `ui.select`로 조건 추가 |
| `course_card` | `CourseCard` | `ui.expansion` + `eval_bar` + 배지 + ⓘ 근거 |
| `eval_bar` | 평가 비율 dict | 가로로 나눈 막대 하나, 항목별 고정 색, 없으면 "미입력" |
| `charts` | 주차별 부담, 시뮬레이션 결과 | `ui.echart` (쌓은 막대, 막대+오차) |
| `strategy_tree` | 트리 JSON | `ui.mermaid` 흐름도 문자열 생성 |

**색**: 과목 색은 8색 팔레트에서 담은 순서대로 정하고, 모든 화면에서 같은 과목은 같은 색이다. 색만으로 뜻을 전하지 않도록 격자 블록에는 항상 과목 이름을 쓴다.

## 테스트

- API: FastAPI `TestClient`로 각 라우트가 `schemas` 형식을 지키는지
- 화면: NiceGUI 테스트 도구(`nicegui.testing`의 사용자 시뮬레이션)로 "과목 담기 → 만들기 → 필터 → 상세" 흐름 하나
- 목업 ↔ 실제 service가 같은 형식을 돌려주는지 (같은 pydantic 모델로 검증)
- 실시간 모드: 휴대폰 폭(400px)에서 버튼이 화면 안에 들어오는지 직접 확인
